# Unity SpriteAtlas V2

Provides *editor-safe* procedural knowledge for scripting atlases in Unity projects. **V2 enforces strict separation between editor authoring and runtime access.**

> ⚠ **Critical V2 Principle**: `SpriteAtlas` is **runtime-only**. `SpriteAtlasAsset` is **editor-only**. Never mix contexts. Always use V2.

## 🚨 CRITICAL: Required Checks and User Inputs Before Implementation

**ALWAYS perform these checks and ask these questions BEFORE generating any code:**

### Read the shipped resources before writing code (REQUIRED)

The atlas code that goes wrong is almost always code written without reading the shipped C# first. Open the files for the path you are taking, then write: [resource-map.md](references/resource-map.md) maps each path to them and covers the other files in `resources/`, which you should browse rather than invent an approach for. Reaching for the API from memory is the most common cause of an atlas that imports cleanly and then does nothing at runtime.

### 0. Check for Existing Scripts (REQUIRED FIRST STEP)

**BEFORE generating any code, scan the project for existing SpriteAtlas scripts generated by this skill**, by searching for the identifier `// [UNITY-SKILL:SPRITEATLAS]`. **If any are found, ALWAYS ask the user before writing anything**: Option A updates them, Option B creates new scripts with different names, Option C aborts and keeps them. The exact question and the handling for each choice are in [existing-scripts-check.md](references/existing-scripts-check.md).

### 1. Delivery Mechanism (REQUIRED)

Ask "How do you want to deliver the sprite atlases?" and read [delivery-mechanism.md](references/delivery-mechanism.md): it compares Built-in data against Addressables late-binding, with the trade-offs and the use cases that fit each.

### 2. SpritePacker Mode (REQUIRED)

**Enable Sprite Packer mode before creating atlases, then read the setting back and confirm it took.**
Use [resources/enablespritepacking.cs](resources/enablespritepacking.cs), which sets `EditorSettings.spritePackerMode` and the importer's packing settings. `Disabled` is the zero value, so an atlas created while it is Disabled still imports and looks finished but can never pack: read the value back, confirm it is **not** `Disabled`, and report what you read. If you cannot read it back, say so rather than assuming the write landed. See [sprite-packer-mode.md](references/sprite-packer-mode.md).

**DO NOT edit meta files DIRECTLY.**

## 🚨 CRITICAL: Default Approach is Prebuild Generation

**ALWAYS use `IPreprocessBuildWithReport` to generate or update SpriteAtlases during the build pipeline**; it is the DEFAULT and REQUIRED approach unless the user EXPLICITLY requests manual authoring.

### ❌ DO NOT Create Manual Menu Item Scripts

**NEVER create scripts with `[MenuItem]` attributes for atlas generation unless explicitly requested**, because the prebuild approach removes the need for manual clicks. **Only use manual authoring for**: Hand-optimized layouts, specific sprite arrangements, or editor preview requirements. See [Advanced: Manual Authoring](#advanced-manual-authoring-not-default---use-only-when-explicitly-requested).

## 🚨 CRITICAL: Sprite Source Location Restriction

**ONLY add sprites from the project's Assets folder. NEVER add sprites from Unity built-in assets, packages, or external locations.** Unity built-in assets cannot be packed into SpriteAtlas, and package assets may cause import/dependency issues.

## Prerequisites

Unity 6000.3 or later, with familiarity in the asset import pipeline and editor scripting for atlas authoring.

## Quick Start: Automated Prebuild Generation (DEFAULT APPROACH)

**This is the PRIMARY and DEFAULT way to create SpriteAtlases**: `IPreprocessBuildWithReport` generates or updates them before each build from your categorization rules.

**Step 1: Ask for the delivery mechanism.** Before generating code: "How do you want to deliver the sprite atlases: (A) Built-in data or (B) Late-binding via Addressables?"

**Step 2: Create the prebuild script** in an Editor folder, customized to that choice; [complete-workflow.md](references/complete-workflow.md) traces both branches end to end.

### Option B: Late-Binding via Addressables (On-Demand Loading)

> 🚨 **CRITICAL ENFORCEMENT**: When user chooses Addressables, you MUST generate ALL THREE scripts below. Never generate just one or two - all three are required for Addressables delivery to work.

**Required Scripts (ALL THREE MANDATORY):**

1. **Prebuild script** (`IPreprocessBuildWithReport`) - generates atlases and Addressables entries
2. **Build Addressables script** (`IPostprocessBuildWithReport`) - builds the content bundles
3. **Late-binding runtime loader** (MonoBehaviour) - loads on demand at runtime

See [references/addressables-delivery.md](references/addressables-delivery.md) for complete implementation.
